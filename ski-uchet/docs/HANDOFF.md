# Промт для новой сессии

Текст ниже можно целиком вставить в новую сессию Claude Code — она подхватит контекст.
Файл обновляется по мере работы: если что-то изменилось, правь его, а не переписывай промт заново.

---

Продолжаем проект, начатый в предыдущей сессии. Отвечай по-русски.

**Проект.** Система учёта средств контроля и измерений (СКИ) в строительном контроле:
геодезические приборы, адгезиметры, средства визуально-измерительного контроля.
Комплект приборов закреплён приложением к договору с заказчиком, на каждом участке
строительства свой комплект. Задача — упорядочить и автоматизировать учёт,
контроль комплектности и сроков поверки.

**Где всё лежит.** Код и документы в папке `ski-uchet`. Прочитай в первую очередь,
до любых изменений:

- `ski-uchet/docs/PROGRESS.md` — журнал: что сделано, что решено и почему;
- `ski-uchet/docs/ROADMAP.md` — план по этапам, технические решения, риски;
- `ski-uchet/docs/QUESTIONS.md` — 57 вопросов заказчику, 42 с ответами.

**Что уже работает.** Веб-приложение на Python (FastAPI + SQLAlchemy + SQLite,
интерфейс на Jinja2), 34 теста проходят. Реестр приборов по инвентарным номерам,
договоры и участки, комплект по договору с автоматической сверкой «требуется → факт»,
поверки с расчётом сроков, журнал выдачи и возврата, заявки на перемещение
с согласованием, типовые комплекты, выгрузки CSV для Excel.

Запуск: `pip install -r requirements.txt`, затем `python manage.py seed-demo`
и `python manage.py run`. Тесты: `pytest -q`.

**Правила учёта зашиты в код, а не в инструкцию:**

1. Прибор нельзя выдать на второй участок, пока не оформлен возврат.
2. Прибор в ремонте, на поверке или списанный выдать нельзя.
3. Прибор с просроченной поверкой выдать нельзя — только с явной отметкой.
4. Брак по поверке снимает прибор с участка и отправляет в ремонт.
5. Возврат со статусом «в ремонте» требует описания неисправности.
6. Заявку на перемещение можно подать только на прибор, закреплённый за участком;
   одна открытая заявка на прибор; отказ невозможен без комментария; согласование
   сразу исполняет перемещение с записями в журнал.

**Ключевые решения заказчика (все блокирующие вопросы закрыты):**

- Система живёт на **сервере конторы внутри локальной сети**, наружу не выставляется:
  ни проброса портов, ни домена, ни сертификата.
- На сайте работают только офисные роли: администратор, кладовщик (МОЛ),
  главный инженер — он согласует заявки.
- **Инженеры строительного контроля они же мастера участков работают только через бота
  в мессенджере MAX**, учётные записи на сайте им не нужны. Бот через long polling
  (исходящие запросы), не вебхуки — иначе пришлось бы открывать порт наружу.
- В боте: заявка на перемещение (главное), подтверждение получения, сдача исправного
  прибора на склад, возврат по неисправности с описанием, фото акта или повреждений,
  свой комплект и сроки поверок. Вход по коду-приглашению от администратора.
- Мастер видит только свой участок. Напоминания о поверках получают мастер,
  главный инженер и руководитель строительного контроля.
- Парк 150-500 приборов, может больше. Все приборы свои. Учитываем только средства
  измерений. Требование в комплекте задаётся только по типу прибора.
- Межповерочный интервал берётся из паспорта прибора.
- Инвентарные номера присвоены и уникальны. Историю поверок не переносим —
  начинаем с текущего состояния.
- Сканы храним: свидетельства о поверке, паспорта приборов, сертификаты калибровки,
  акты и накладные. Договоры не храним.
- Вход по СМС отклонён: логин с паролем и восстановление по почте.
- Доступ заказчику в систему закрыт.

**Что дальше по плану.**

Этап 1 — импорт реестра приборов из Excel заказчика и справочники.
Этап 2 — переезд на PostgreSQL, развёртывание на сервере конторы, роли и вход,
журнал действий, резервные копии.
Этап 3 — документы: акт выдачи по утверждённой форме, перечень СИ на объект, журнал СИ.
Этап 4 — вложения: файл к прибору, поверке, акту. У вложения два измерения —
источник (бот или сайт) и назначение.
Этап 5 — метрология вглубь: заявки на поверку, график на год, бюджет.
Этап 6 — бот в MAX для инженеров СК.
Этап 7 — уведомления и аналитика.

**Чего ждём от заказчика:** файл реестра приборов в Excel и утверждённую форму акта
выдачи. Без них первый и третий этапы не начать.

**Открытые вопросы:** 19-22 (документы для заказчика), а также 5, 11, 13, 14, 16, 17,
27, 28, 29, 31, 32, 47 — они нужны к более поздним этапам. Полный список с формулировками
в `docs/QUESTIONS.md`.

**Как вести работу.** Все решения и ответы заказчика записывай в `docs/PROGRESS.md`
с обоснованием, план держи в актуальном состоянии в `docs/ROADMAP.md`, вопросы
и ответы — в `docs/QUESTIONS.md`. Коммить осмысленными порциями. Заказчику удобнее
отвечать на вопросы с готовыми вариантами в формате «33а, 34б,в».

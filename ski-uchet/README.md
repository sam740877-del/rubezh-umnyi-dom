# Учёт СКИ — средства контроля и измерений на участках строительства

Приложение для строительного контроля: учёт приборов (геодезия, адгезиметры, ВИК),
их закрепление за участками по договору, контроль комплектности и сроков поверки.

**Что решает:**

- один реестр приборов вместо разрозненных таблиц Excel;
- комплект приборов по каждому договору/участку и автоматическая сверка «требуется → факт»;
- календарь поверок: просроченные, истекающие, приборы без документов;
- журнал выдачи и возврата приборов с указанием ответственного и номера акта;
- запрет на выдачу прибора с просроченной поверкой (с осознанным «выдать принудительно»);
- выгрузки в CSV для Excel и отчётности заказчику.

Стек: **Python 3.11+, FastAPI, SQLAlchemy, SQLite, Jinja2**. Внешних сервисов не требует,
работает локально, база — один файл `ski.db`.

## Быстрый старт

```bash
# 1. Виртуальное окружение
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

# 2. Зависимости
pip install -r requirements.txt

# 3. Справочник типов приборов (33 позиции: геодезия, адгезия, ВИК, климат, электро)
python manage.py seed-types

# 4. Запуск
python manage.py run
```

Открыть в браузере: <http://127.0.0.1:8000>

Чтобы посмотреть, как всё работает на заполненных данных (2 договора, 3 участка, 24 прибора):

```bash
python manage.py reset --yes
python manage.py seed-demo
python manage.py run
```

Чтобы приложение было доступно с других устройств в локальной сети (планшет прораба):

```bash
python manage.py run --host 0.0.0.0 --port 8000
```

## Команды `manage.py`

| Команда | Что делает |
|---|---|
| `python manage.py init` | создать таблицы в пустой базе |
| `python manage.py seed-types` | заполнить справочник типов приборов |
| `python manage.py seed-demo` | залить демонстрационные данные |
| `python manage.py stats` | сводка в консоли: приборы, поверки, комплектность участков |
| `python manage.py reset --yes` | удалить и пересоздать базу |
| `python manage.py run [--host --port --reload]` | запустить веб-приложение |

Путь к базе можно переопределить переменной окружения `SKI_DATABASE_URL`
(например, `sqlite:///D:/work/ski.db` или строка подключения к PostgreSQL).

## Структура данных

```
Договор (contracts)
   └── Участок (sites)
          ├── Комплект по договору (kit_items): тип прибора × требуемое количество
          └── Приборы, фактически находящиеся на участке
Прибор (instruments) ── тип (instrument_types) ── межповерочный интервал
   ├── Поверки/калибровки/ТО (verifications)
   └── Журнал движения (movements): выдача / возврат
```

**Ключевые таблицы**

- `instrument_types` — справочник типов: категория, нужна ли поверка, интервал в месяцах.
- `contracts` — договоры с заказчиком.
- `sites` — участки строительства в рамках договора, с ответственным лицом.
- `kit_items` — комплект, требуемый на участке по договору (тип + количество).
- `instruments` — экземпляры приборов по инвентарным номерам, статус и текущий участок.
- `verifications` — поверки: дата, срок действия, свидетельство, организация, результат.
- `movements` — журнал выдачи/возврата: дата, участок, ответственный, номер акта.

**Статусы прибора:** на складе · на участке · на поверке · в ремонте · списан.

## Правила учёта, зашитые в приложение

1. Прибор нельзя выдать на участок, если он уже числится на другом — сначала возврат.
2. Прибор со статусом «на поверке», «в ремонте» или «списан» выдать нельзя.
3. Прибор с просроченной поверкой (или без данных о поверке) выдать нельзя —
   только с явной отметкой «выдать несмотря на просроченную поверку».
4. Поверка с результатом «брак» автоматически переводит прибор в ремонт и снимает с участка.
5. Если при регистрации поверки не указан срок действия, он считается автоматически:
   дата проведения + межповерочный интервал типа прибора.
6. Статус «на участке» ставится только через операцию выдачи, вручную его не выставить.
7. Комплектность участка считается по фактически закреплённым приборам:
   излишки сверх требуемого количества не компенсируют дефицит по другим позициям.

## Разделы интерфейса

| Раздел | Назначение |
|---|---|
| **Сводка** | приборный парк, просроченные и истекающие поверки, готовность участков |
| **Приборы** | реестр с поиском и фильтрами, карточка прибора, выдача/возврат, поверки |
| **Участки** | комплект по договору, сверка «требуется → факт», дефицит, выдача на участок |
| **Договоры** | реестр договоров и связанных с ними участков |
| **Поверки** | календарь на выбранный горизонт (по умолчанию 60 дней) |
| **Журнал движения** | все выдачи и возвраты, фильтр по участку |
| **Справочник типов** | типы приборов и межповерочные интервалы |

**Выгрузки CSV** (открываются в Excel без настройки кодировки):

- `/export/instruments.csv` — весь реестр приборов;
- `/export/site-<id>.csv` — комплектность конкретного участка;
- `/export/verifications.csv?days=60` — план поверок.

API-документация доступна на `/api/docs`.

pip install -r requirements.txt

участка, а также дымовые тесты всех страниц и выгрузок. Тесты работают на отдельной
временной базе и рабочую `ski.db` не трогают.

## Возможное развитие

- печать акта приёма-передачи приборов (PDF) прямо из карточки участка;
- импорт существующего реестра приборов из Excel;
- учётные записи и роли (кладовщик / прораб / руководитель);
- уведомления о поверках на почту или в мессенджер;
- фотофиксация свидетельств о поверке (вложения к записи поверки);
- переезд на PostgreSQL при работе нескольких офисов — код к этому готов,
  меняется только `SKI_DATABASE_URL`.
